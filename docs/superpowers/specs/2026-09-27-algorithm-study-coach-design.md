# 算法学习教练设计文档

- 日期：2026-09-27
- 状态：设计已确认，待评审

## 1. 背景与目标

本作品面向准备算法与数据结构考试或技术面试的用户，主要服务对象是在牛客
平台使用 C++ 刷题的学生。系统通过浏览器插件自动记录用户的刷题过程，基于
解题历史诊断薄弱知识点，并针对单道题提供讲解、分步提示和多解 C++ 代码。

目标是把散落的刷题行为变成可量化、可回顾、可指导的学习闭环：用户在平台
上正常做题，系统在后台形成个人能力画像，并给出下一步该练什么。

## 2. 范围

### 本期包含

- 牛客平台浏览器插件，抓取题目页和已通过题目列表。
- 本地后端，保存题目、提交记录、知识点标签和大模型缓存。
- 掌握度计算、薄弱点诊断和题目推荐。
- 单题讲解、渐进式提示、多解 C++ 代码生成。
- React 看板，展示薄弱点、推荐题目和单题详情。
- 演示数据导入能力，用于没有历史提交记录时展示完整效果。

### 本期不包含

- LeetCode 等其他平台接入。
- 在线判题或代码执行功能。
- 云端部署、账号体系或多人协作。
- 自动发布到浏览器应用商店。

## 3. 用户与成功标准

### 目标用户

- 使用 C++ 在牛客刷题的在校学生。
- 需要准备算法与数据结构考试或技术面试的个人用户。

### 成功标准

- 用户在牛客完成一道题后，插件能在 30 秒内把记录同步到本地看板。
- 看板能根据历史记录给出至少一个薄弱知识点和对应推荐题目。
- 单题页面能展示讲解、至少三层渐进提示和两种以上 C++ 解法。
- 演示时即使没有历史记录，也能通过导入演示数据走完整条链路。

## 4. 架构与组件

系统由三个本地组件组成。

### 4.1 浏览器插件

- 使用 Chrome/Edge 的 Manifest V3。
- 内容脚本识别牛客题目页、个人已通过题目列表和题库列表。
- 在题目页捕获题目标题、难度、标签、用户代码和提交结果。
- 弹窗提供同步状态、手动补录和设置后端地址。
- 不读取或外传牛客账号 Cookie，只提交已解析的结构化数据。

### 4.2 本地后端

- 使用 Python 和 FastAPI。
- 接收插件提交的解题事件，做清洗、去重和入库。
- 维护算法与数据结构知识点分类体系。
- 调用大模型完成知识点归类、讲解、提示和多解生成。
- 计算掌握度并输出薄弱点诊断和推荐题目。
- 结果缓存到 SQLite，降低大模型调用成本。

### 4.3 学习看板

- 使用 React、Vite、Tailwind、Recharts 和 lucide-react。
- 首页展示已刷题数、通过率和知识点掌握度图。
- 知识点页展示该知识点的通过率、薄弱程度和推荐题目。
- 题目页展示讲解、渐进提示和多解对比。
- 提供演示数据导入入口。

## 5. 数据流

### 5.1 记录与诊断流程

1. 用户在牛客提交代码。
2. 插件读取题目信息、用户代码和提交结果。
3. 插件把事件发送到本地后端，后端按题目和事件特征去重。
4. 后端为题目匹配知识点标签并保存记录。
5. 后端按知识点聚合记录，计算掌握度。
6. 看板按掌握度排序，把低掌握度知识点展示为薄弱点并推荐题目。

### 5.2 单题讲解流程

1. 用户在看板打开某道题。
2. 后端按题目和用途查询缓存。
3. 缓存未命中时调用大模型生成讲解、提示和多解，并写回缓存。
4. 看板展示结果，提示采用渐进式呈现。

## 6. 数据模型

### problem

- id：主键。
- platform：平台标识，固定为 niuke。
- source_id：牛客题目原始编号。
- title：题目标题。
- difficulty：简单、中等、困难。
- url：题目链接。
- description：题目描述，可选。

### solution_record

- id：主键。
- problem_id：关联题目。
- status：accepted、wrong、time_limit、compile_error、runtime_error。
- language：固定为 cpp。
- code：用户提交的代码文本。
- time_cost_ms：耗时，可选。
- memory_cost_kb：内存，可选。
- submitted_at：提交时间。
- event_key：用于幂等去重的唯一键。

### tag

- id：主键。
- name：知识点名称，如 dynamic_programming。
- display_name：展示名称，如动态规划。

### problem_tag

- problem_id：关联题目。
- tag_id：关联知识点。
- confidence：匹配置信度，0 到 1。

### llm_cache

- id：主键。
- cache_key：题目、用途、模型和提示的哈希。
- provider：模型提供方。
- model：模型名。
- output：生成结果。
- created_at：创建时间。

## 7. 掌握度与推荐

### 7.1 知识点分类体系

系统内置一组常见算法与数据结构标签，包括但不限于：数组、字符串、哈希表、
双指针、滑动窗口、栈、队列、链表、二叉树、堆、图、广度优先搜索、深度优先
搜索、并查集、排序、二分查找、贪心、动态规划、回溯、位运算、数学。

题目标签优先使用牛客已有标签，缺失或不足时由大模型补充分类。

### 7.2 掌握度计算

对某个知识点 t，定义：

- 难度权重：简单 0.8，中等 1.0，困难 1.3。
- 时间权重：0.5 + 0.5 * exp(-days_since / 30)，其中 days_since 是距离当前
  时间的天数。
- 单条记录权重 = 难度权重 * 时间权重。

先过滤掉同一道题在后来已经通过之前的失败记录。设：

- weighted_accepted：该知识点下所有通过记录的权重之和。
- weighted_failed：该知识点下剩余失败记录的权重之和乘以 0.5。
- smoothing：0.5。

掌握度 = 100 * weighted_accepted / (weighted_accepted + weighted_failed +
smoothing)，结果限制在 0 到 100。

### 7.3 薄弱点与推荐

- 掌握度越低，薄弱程度越高。
- 知识点按掌握度升序排列，掌握度最低且有过练习记录的知识点优先标记为薄弱点。
- 推荐题目优先来自薄弱知识点，并按知识点薄弱程度、题目难度和未完成状态排序。
- 近期反复失败的题目适当降低推荐优先级，避免制造挫败感。

## 8. 大模型集成

- 使用 OpenAI 兼容客户端，API Key 和模型名可在配置中替换。
- 用途一：题目知识点归类，输入标题和描述，输出标签和难度。
- 用途二：生成讲解，输出解题思路和时间复杂度。
- 用途三：生成渐进提示，输出三层提示，从思路到实现逐步递进。
- 用途四：生成多解 C++ 代码，至少包含暴力解和较优解。
- 所有结果按 cache_key 缓存，避免重复调用。

## 9. 错误处理与降级

- 牛客页面结构变化时，内容脚本使用多重选择器并逐步降级。
- 抓不到完整字段时，允许用户在看板或弹窗中手动补录题目。
- 后端不可用时，插件把事件暂存在 chrome.storage，稍后重试。
- 大模型调用失败时，优先返回缓存；无缓存则给出可重试的错误提示，不阻塞看板。
- 重复事件通过 event_key 幂等处理，避免同一提交被统计多次。

## 10. 测试策略

- 单元测试：掌握度计算、时间衰减、题目去重和推荐排序。
- 接口测试：后端 CRUD、事件接收、幂等和缓存命中。
- 端到端冒烟测试：从插件模拟事件到看板展示的完整链路。
- 人工验证：在真实牛客题目页验证抓取选择器和降级逻辑。

## 11. 技术选型

- 浏览器插件：Manifest V3、TypeScript。
- 后端：Python、FastAPI、SQLAlchemy、SQLite。
- 大模型：OpenAI 兼容客户端，Key 可替换。
- 看板：React、Vite、Tailwind、Recharts、lucide-react。
- 本地运行：后端监听 localhost，插件和看板均连接本地地址。

## 13. 风险与缓解

- 牛客页面结构变化：使用多重选择器、手动补录和演示数据兜底。
- 大模型调用不稳定或产生幻觉：缓存结果，限制输出结构，并在看板提示为生成内容。
- 单人和时间紧张：严格控制平台范围为牛客，砍掉非核心功能。
- 没有历史提交记录：提供演示数据导入，并让插件从当前刷题开始积累记录。

## 14. 假设与约束

- 用户拥有可登录的牛客账号，并使用 Chromium 内核浏览器。
- 用户有可用的大模型 API Key。
- 本地环境可运行 Python 和 Node.js。
- 本期只支持 C++ 解法生成，不接入其他平台。
